# Two-SLR benchmark variants with platform integration

The user authorizes scaling, realistic clock/reset/AXI integration, and explicitly labelled multi-engine CNNA replication. Preserve the existing OOC baselines and source hashes.

Use the installed xilinx_u250_gen3x16_xdma_4_1_202210_1 platform with Vitis/Vivado 2023.2. Target kernel clock is 100MHz, generated by the real platform. Kernels do not insert BUFGs, invent input/output delays, or add blanket false paths. Standard proc_sys_reset connects the platform clock/reset and provides synchronized peripheral reset. Generated parameters must show external reset active low and auxiliary reset active high tied inactive. Reset release and AXI buffering add initialization/transaction latency but do not alter arithmetic.

VTA64 is one 64x64 tensor engine at batch 1, with 128KiB input, 256KiB weight, 512KiB accumulator and 32KiB uop storage. Its original four-stage instruction/dependency architecture is retained. Constrain accelerator placement to SLR2/SLR3; actual measured occupancy determines success. HLS estimates alone do not establish mapped DSP usage or two-SLR occupancy.

CNNA6 is six independent copies of the unchanged upstream cnn_top engine, three assigned to SLR2 and three to SLR3. This is multi-core throughput scaling, not a larger individual convolution array. Each engine receives a memory/stream adapter, separate control registers and DDR access. There is no claim of a single inference automatically distributed across the six engines.

Each CNNA adapter has four concurrent input readers and one output writer. A 256-bit memory record stores payload, TKEEP and TLAST; for 128-bit packets these occupy bits 127:0, 143:128 and 144; for 64-bit control packets, bits 63:0, 71:64 and 72. Host supplies exact packet counts. Protocol backpressure is preserved through HLS AXI streams and standard register slices. Adapter dataflow is not the compute architecture.

The AXI-Lite control window is 64KiB with 4KiB pages. CNNA DMA is page 0, CNN status/control page 1. VTA stage CONTROL_BUS pages 0..3 and pointer-control pages 4..7. Memory masters are explicitly 64-bit addressed. Generated address maps and pointer-register metadata are authoritative. User-managed XRT control requires host software; it is not the original PYNQ driver.

Full-platform routing/timing and accelerator-only SLR/resource reporting are separate. Shell occupancy never counts toward the two-SLR accelerator requirement. Export a new routed checkpoint and configuration only on the server, independently reopen it, archive compact reports, and keep failures visible. No physical board is available for execution validation.

Known test issue: upstream VTA ALU oracle unconditionally reads a nonexistent second input in immediate mode; an auditable copied test oracle fixes this. The blocked-GEMM test must have at least two outer blocks for its two virtual threads, so scaled test dimensions are adjusted. Neither change touches accelerator sources. Test-only changes and ASAN results must be distinguished from unchanged upstream test success.
